# Статистика голосов по варианту опроса + ничья в боте

Дата: 2026-07-29  
Статус: согласовано, в реализации

## Проблема

В Telegram-миниаппе на карточке голосования статистика — общий список «Кто голосовал». Бизнес хочет по клику на вариант видеть таблицу «пользователь → итог заслуг» именно за этот вариант (сумма кастов пользователя).

Дополнительно: при ничьей бот в чате объявляет победителем только верхний вариант с максимальным `amount`.

## Решение

1. **API:** `polls.getCasts` при переданном `optionId` агрегирует `casters` только по этому варианту (сейчас `casters` всегда по всему опросу).
2. **UI (`community-web`):** тап по варианту выбирает его для голосования и раскрывает под ним таблицу итогов по пользователям; нижняя лента без изменений.
3. **Бот:** в `buildPollResultsMessage` все варианты с максимальным `amount` — победители; формулировка «Победитель» / «Победители».

## Детали

### Таблица под вариантом

- Колонка итог: `totalUp − totalDown`, цвет `+` / `−`.
- Данные: `getCasts({ pollId, optionId, limit: 1 })` → поле `casters`.
- Закрытый опрос: тап всё равно раскрывает таблицу (без каста).
- Раскрыт максимум один вариант (тот же, что выбран).

### Ничья

- Один максимум → `Победитель: «X» (N заслуг)`.
- Несколько → `Победители: «A», «B» (по N заслуг)`.
- `totalCasts === 0` → строки нет.

## Вне скоупа

Основной web UI опросов, пагинация casters сверх лимита, изменение нижней ленты.
