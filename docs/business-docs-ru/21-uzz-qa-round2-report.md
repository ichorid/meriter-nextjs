## Решения по продукту (подтверждены владельцем)

- **Контакт без @username** — вариант A: контакт сделки хранит `telegramUserId` рядом с необязательным `telegramUsername`; при отсутствии username UI даёт ссылку `tg://user?id=…`. Никого не блокируем.
- **Порог эмиссии** остаётся **на пост**, правило не менялось. Исправлены только объяснение в интерфейсе и застрявшие случаи.
- **Длительность / место / доступность** остаются свободным текстом, добавлены подсказки.
- **4.36 / 4.37 (таймеры истечения и таяния) — не баг.** Истечение заявок и таяние номинала привязаны к фоновому тику (почасовому и суточному), а не к индивидуальному таймеру. Наблюдения тестера точны: задержка до ~1 часа для заявок и 24–48 ч до первого таяния в зависимости от времени создания. Так задумано, зафиксировано в [runbook](18-uzz-pilot-runbook.md).

## Не воспроизведено

- **6.8 «Enter на „Добавить услугу“ не работает».** Кнопка — настоящий `<button>` с `onClick`; Enter на ней срабатывает. В браузерном тесте (`uzz-responsive.spec.ts`, 4 viewport'а) форма открывается и полностью видна. Наиболее вероятно, что форма открывалась и раньше, но терялась под карточками из-за дефекта раскладки 6.1 — он исправлен. **Требует перепроверки на стенде** (строка 7.18 сессии 07); если повторится — заводить заново с видео.

## Найдено попутно

- В `deals-page.test.tsx` дата в фикстуре была захардкожена как `2026-08-20` и «протухла» 20 августа: тест начал падать сам по себе, независимо от изменений. Заменена на относительную. Стоит поискать такие же бомбы времени в остальных наборах.

**Шаги 8 и 9 выполнены в CI, не локально:** оба требуют Compose-стенда `uzz-e2e`, а Docker Desktop на машине поднять не удалось. GitHub Actions прогнал их на коммите `477f168a` — оба зелёные, дальше прошёл выкат на dev-сервер.

Первый прогон этого коммита упал на шаге `UZZ real E2E`: docker-build образа api вернул exit 1 на `pnpm --filter @meriter/shared-types... install --frozen-lockfile`. Причина не в изменениях — диапазон `7ecd47bf..477f168a` не трогает ни один `package.json`, ни `pnpm-lock.yaml`, ни Dockerfile, ни compose, а корневой `pnpm install --frozen-lockfile` в том же job'е прошёл. Перезапуск без единой правки дал зелёный результат, то есть сбой транзиентный (выкачивание пакетов в слое docker). **Если повторится — смотреть в эту сторону, а не в код.**

Миграция данных не требуется: старые сделки читаются через `restoreContact` в `uzz-mappers.ts` и отдают `telegramUserId: ''`, что на фронте деградирует к прежней ссылке по username. Это закреплено тестом «reads deals accepted before contacts carried a telegram user id» в `uzz-persistence.spec.ts`. Поля контакта в манифесте индексов не участвуют (19 индексов, ни одного по контакту).

Раскладочные фиксы дополнительно закреплены браузерными тестами в `uzz-web/e2e/uzz-responsive.spec.ts`: кнопки каждой карточки остаются внутри своей ячейки, инлайн-редактор раскрывается внутри карточки — на всех четырёх viewport'ах.
