# 16. «Услуги за заслуги» — продуктовое ТЗ пилота (MVP)

**Статус:** зафиксировано для реализации  
**База:** выжимка продуктового разговора; docx-ТЗ ideолога — только фон  
**Связанные:** [10-telegram-mvp.md](./10-telegram-mvp.md), [12-community-web-mvp.md](./12-community-web-mvp.md), [13-telegram-stack-deployment-ru.md](./13-telegram-stack-deployment-ru.md)

## 1. Цель пилота

Проверить, что обмен товарами/услугами за «банки», эмитированные из признанных добрых дел, воспринимается как справедливый и запускает оборот внутри сообщества.

Денег внутри контура нет. Рублёвый номинал банка — игровой потолок сделки, не обязательство оператора.

## 2. Поверхности

| Канал | Роль |
|-------|------|
| Telegram (существующий бот) | Добрые дела, начисление заслуг, опциональные уведомления, привязка email |
| `uzz-web` (площадка) | Каталог, банки, сделки, кошелёк/история, админка; вход только по email |
| Dev | Прогон до приёмки |
| `cw.ru` | Prod после приёмки на dev |

**Нельзя:** Telegram Login Widget (ограничения РФ).  
**Можно:** email magic link + двусторонняя привязка TG ↔ аккаунт сайта.

## 3. Язык UI

Используем: **заслуга**, **доброе дело**, **банк**, **услуга/товар**, **сделка**, «номинал сегодня N ₽».  
Не используем в UI: токен, демерредж, гезелль, NFT, джокер.

## 4. Числовые дефолты пилота

| Параметр | Ключ | Дефолт |
|----------|------|--------|
| Порог эмиссии банка | `emissionThreshold` | `10` заслуг на добром деле |
| Начальные ходы банка | `bankInitialHops` | `10` (= порогу) |
| Таяние номинала | `demurrageRubPerDay` | `100` ₽/сутки |
| Пол номинала | `nominalFloorRub` | `100` ₽ |
| Мин. карточек (жёсткий режим) | `minLotsToBuy` | `3` |
| Допуск к покупке | `purchaseGate` | `nudge` (`nudge` \| `require_min_lots`) |
| Режим передачи банка | `bankTransferMode` | `escrow_until_close` |
| Срок ответа на заявку | `dealRequestTtlHours` | `48` |
| Срок исполнения по умолчанию | `dealFulfillmentDays` | `7` |

Режимы `bankTransferMode`: `escrow_until_close` (дефолт) \| `on_accept_locked` \| `on_close_only`.

## 5. Сквозной сценарий

1. Участник публикует доброе дело в TG; сообщество начисляет заслуги (как сейчас).
2. При `merits >= emissionThreshold` система создаёт банк `awaiting_nominal` (если TG↔email связан; иначе holding + пинг на привязку).
3. Админ назначает номинал вручную → банк `active`.
4. Участник на площадке создаёт карточки услуг/товаров; при `nudge` видит баннер до `minLotsToBuy`.
5. Владелец банка выбирает карточку с `priceRub <= nominalRub`, отправляет запрос (нужен ≥1 заслуга на wallet — комиссия).
6. Исполнитель принимает или отклоняет. При accept (дефолт): банк в эскроу (`in_deal`).
7. Исполнитель отмечает «сделано»; заказчик подтверждает закрытие (или админ вручную).
8. При закрытии: банк → исполнителю; `hopsLeft -= 1`; с wallet покупателя −1 заслуга; `dealAmountRub = nominalRub` на момент закрытия.
9. Опционально форма благодарности (заслуги + комментарий) — не блокер.
10. Раз в сутки cron уменьшает номинал банков в `active` и `in_deal` на `demurrageRubPerDay`, не ниже `nominalFloorRub`. При `hopsLeft = 0` → `exhausted`.

## 6. Правила экономики

- Банк — передаваемый объект, не баланс.
- Сдачи / частичного списания номинала нет.
- Комиссия — всегда с **wallet**, не с квоты.
- Сделка внутри контура **не** эмитирует новый банк.
- Новый банк — только из нового доброго дела после порога.

## 7. Идентичность

1. Логин сайта: email magic link → сессия продукта `uzz`.
2. Сайт → TG: профиль «Укажите Telegram» → deep-link/код в бота → link в БД.
3. Бот → сайт: «Укажите почту» → OTP на email → тот же link.
4. Без связки: каталог можно смотреть; банки/сделки/TG-кошелёк на сайте — с блокером привязки.

## 8. Сущности

`UzzSettings`, `GoodDeed` (ссылка на publication), `Bank`, `Lot`, `Deal`, `UzzLedger`.

**Bank statuses:** `awaiting_nominal` → `active` → `in_deal` → `active` (новый владелец) → `exhausted` (также holding при отсутствии link).

**Deal statuses:** `requested` → `accepted` → `completed_by_seller` → `closed` (+ `rejected` / `cancelled`).

## 9. Экраны MVP

Участник: главная (банки), каталог, карточка, мои услуги, сделки, кошелёк/история, добрые дела, профиль.  
Админ: очередь номиналов, настройки, сделки + ручной возврат, ledger.  
Бот: привязка email + настраиваемые пинги (без тяжёлого UX сделок).

## 10. Out of scope

Абонемент/оплата ₽, автономинал, формульный Gesell, рубрикатор, жюри/споры, NFT/джокер, верификация соцпроектов, корпоративный режим, Telegram Login.

## 11. Критерий готовности к cw.ru

На dev (5–10 человек): дело в TG → банк → номинал → лот → сделка → закрытие → банк у исполнителя; видно таяние; привязка email↔TG в обе стороны; email-логин стабилен.

## 12. Архитектура (кратко)

- Пакет `@meriter/uzz-web` (паттерн community-web).
- Общий `@meriter/api`, product `uzz`, tRPC `/trpc/uzz`.
- Reuse: TG bot, wallet/quota/votes, magic link.
- Не reuse UI большого Meriter.
